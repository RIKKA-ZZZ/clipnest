# 验证与修复记录

## 静态托管

- 网站资源使用相对路径和 import.meta.url，支持 GitHub Pages 的仓库子目录。
- 仅在 localhost / 127.0.0.1 探测本机处理服务，在线页面不访问 `/api/capabilities`。
- `dist/` 中没有服务器文件、素材缓存、Git 元数据或私有托管配置。
- 单线程 WASM 被拆分为四个不超过 8 MiB 的文件，加载时检查 SHA-256，再重组成 WASM Blob；不依赖 SharedArrayBuffer 或跨源隔离响应头。
- GitHub Actions 先执行语法和静态资源检查，再发布 `dist/`。

## 文件选择与进度

首版隐藏 input.click 在内嵌浏览器中可能只产生文件选择请求，没有实际系统窗口。本机模式改为调用 Windows OpenFileDialog；普通浏览器模式使用 showPicker，保留 click 后备和拖拽导入。

处理引擎探测结束前禁用导入按钮，避免用户很快点击时误进入浏览器选择路径。Windows 文件窗口已通过枚举所属测试进程的可见窗口并检查标题验证；带透明父窗口的对话框不适合仅用进程 MainWindowHandle 判断。

导出进度区直接放到按钮下方，点击时立即初始化。显示阶段、实际处理百分比、耗时和取消按钮，完成保持 100%。本机进度来自 FFmpeg out_time_us，浏览器进度来自已编码时间。

## 文件体积

首版用 arrayBuffer 和 WebAssembly 文件系统复制整段输入，并设 300 MiB 上限。现在本机模式从磁盘流式读取，输入上限 10 GiB；浏览器通过 WORKERFS 只读挂载 File，输入上限 1 GiB。

350 MiB 测试容器含 free-box 填充，用于验证大文件输入、磁盘读取与 HTTP 流式传送，不能替代真实高码率 / 4K 压力测试。本机输出超过 2 GiB 时跳过 ZIP。

## 已修复的兼容问题

- core 0.12.10 的 ffprobe 在输出有效 JSON 时可能返回 -1。通过验证输出 JSON 和媒体轨道兼容该情况，见 [上游 issue #817](https://github.com/ffmpegwasm/ffmpeg.wasm/issues/817)。
- 本地服务曾把根目录误判为目录外路径，返回 403；已允许精确根目录并保留目录边界检查。
- 时间线选区阴影曾溢出遮暗编辑器，现裁切在轨道内。
- ffmpeg.wasm 的通用进度比例对裁切场景不准确，现按实际编码时间除以所选时长计算。

## 已执行验证

- 2.25–5.75 秒片段输出：无声 H.264 MP4 只有视频流，MP3 / WAV 只有音频流，时长在预期编码容差内。
- WAV 为 PCM s16le；无音轨素材有明确提示或跳过原因。
- VP9 / Opus WebM 输入转换为 H.264 / MP3。
- ZIP CRC、中文文件名及说明文本可解析。
- Range 请求、无会话令牌请求、跨来源请求与非法范围检查。
- 30 秒素材导出观察到 11% 中间进度，取消后恢复可用；取消及重试通过。
- 390 px 手机布局无水平溢出。
